# QA Junior Bootcamp para banca web

Este documento describe el programa de onboarding para un QA junior trabajando en un banco con presencia web. Proporciona objetivos, entregables, plantillas y un plan de 6 semanas para alcanzar competencia básica en pruebas de software enfocadas en banca.

## Objetivo
Formar a un QA junior para ejecutar pruebas funcionales, de API, de seguridad, rendimiento y accesibilidad en un entorno bancario web, con evidencia clara y entrega de valor en cada sprint.

## Requisitos previos
- Comprender conceptos básicos de QA y desarrollo de software.
- Acceso a documentación y entornos de prueba (PRD, API docs, runbooks, entorno QA).
- Conocimiento básico de Git y flujo de PR.

## Estructura del bootcamp
- Semana 1: Alineación, entorno y fundamentos
- Semana 2: Casos de prueba funcionales y API
- Semana 3: Seguridad y OWASP Top 10
- Semana 4: Rendimiento y accesibilidad
- Semana 5: Regresión y reporte
- Semana 6: Cierre y mejora continua

## Entregables
- Plan de Pruebas
- Casos de Prueba (funcionales y API)
- Defectos y su ciclo de vida
- Informe de Progreso
- Informe Final con lecciones aprendidas y mejoras

## Plantillas incluidas
- Plan de Pruebas (Markdown)
- Casos de Prueba (Markdown)
- Informe de Defectos (Markdown)
- Informe de Progreso (Markdown)
- Cronograma de 6 semanas (Markdown)

## Plan de 6 semanas (alto nivel)
- Semana 1: Alineación, entorno y plan de pruebas inicial
- Semana 2: Casos de prueba funcionales y API
- Semana 3: Seguridad (OWASP) y pruebas de autenticación
- Semana 4: Rendimiento y accesibilidad
- Semana 5: Regresión y reporte de progreso
- Semana 6: Cierre y mejoras

## Prácticas recomendadas
- Mantener una estructura de pruebas clara y reutilizable.
- Documentar evidencia de cada defecto (capturas, logs, pasos reproducibles).
- Buscar feedback temprano del equipo y mentor.
- Mantener trazabilidad entre requisitos, casos de prueba y defectos.

## Glosario breve
- PRD: Product Requirements Document
- API: Interfaz de Programación de Aplicaciones
- OWASPTop10: Lista de 10 riesgos de seguridad más críticos

## Uso recomendado
- Al comenzar, consulta la documentación disponible y configura tu entorno según la guía de onboarding. Luego, usa las plantillas para crear planes, casos y reportes de forma consistente.
